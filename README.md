# 会话恢复 · 从会话记录里把文件找回来

DSH 的每条会话都是一份**完整的编辑日志**：`write` 存的是全文，`edit` 存的是
「改之前」和「改之后」两段原文。也就是说，只要你在这个会话里写过某个文件，
它的内容就还在磁盘上——哪怕工作区已经被删空、改坏、或者误装成了别的版本。

这个插件读取那些日志，按时间顺序回放，把文件重建出来，**先给你看，再由你决定
写到哪里**。

---

## 为什么需要它

2026-10-27，`dsh-plugin-cloud` 的源码目录在工作过程中被清空，37 个源文件全部
消失。没有 git 仓库、没有备份、回收站里也没有。

但插件最终被完整恢复，测试从 0 项回到 235 项全绿——**唯一的数据源就是会话记录**。
这个过程当时是手写脚本做的，踩了四个坑，每一个都足以让人得出「记录是空的、
没救了」的错误结论：

1. 会话文件是**多帧 zstd 拼接**。`zstdDecompressSync` 只解第一帧，也就是那个
   193 字节的会话头。直接解会得到「里面什么都没有」。
2. 工具调用不在顶层，藏在 `assistant/message` 的 `data.message.content[]` 里，
   而且 `arguments` 是 **JSON 字符串**，不是对象。
3. 只回放 `write` 不够。之后的 `edit` 才是最终状态，必须按 `seq` 顺序回放。
4. 有些改动是 bash 脚本做的，不产生 `edit` 事件。这时后续 `edit` 的
   `old_string` 永远对不上——但 `read` 的结果里存着**文件当时的全文**，包括
   `(Showing lines 96-135 of 278)` 这样的总行数，可以当检查点用来重同步。

这四条现在是插件的实现，不再是某一次事故里的临时脚本。

---

## 能力

| 能力 | 说明 |
|---|---|
| **列出会话** | 扫描所有 profile 的会话，显示时间、目录、事件数、涉及文件数 |
| **预览重建** | 选定会话后重建文件树，先看清单和每个文件的规模 |
| **安全导出** | 写到指定目录，绝不直接覆盖工作区 |
| **冲突提示** | 目标文件已存在时标出来，让你决定覆盖还是跳过 |
| **缺口说明** | 有多少 `edit` 没能应用、哪些文件被 bash 直接改过，如实报告 |

最后一条是这个插件和「一键恢复」的区别：**重建结果可能不完整**，而它不会假装
完整。bash 直接改过的文件、找不到基线的 `edit`，都会被明确标出来。

---

## 用法

装好后在插件页的「会话恢复」标签里：

1. 选一条会话（按时间倒序，最近的在前）
2. 点「预览」，看会重建出哪些文件
3. 确认后点「导出」，选一个空目录

命令行也可以：

```bash
node tools/cli.mjs list
node tools/cli.mjs preview <session-id>
node tools/cli.mjs export <session-id> <target-dir>
```

## 边界

**只恢复得到 `write` / `edit` 记录过的文件。** 会话开始前就存在的文件、纯靠
`bash mv` 或外部工具改的文件，不在日志里，也不会被重建。插件把这种情况单独
列出来（「日志里没有全文」），和「真的丢了」分开报——把两者混成一个数字会
让人误判恢复质量。

**不是时间机器。** 重建出来的是某个会话运行期间的产物，不是某个历史时刻的完整
快照。同一条会话里如果文件被反复改写，得到的是最后状态。

**不动工作区。** 导出写到新目录，插件从不直接覆盖你正在用的目录——这个插件存在
的前提就是「误操作会丢数据」，它自己不该成为新的一次误操作。

## 验证

```bash
node tools/run-all.mjs        # 97 项，3 套
node tools/mutation-check.mjs # 故意破坏实现，确认 12 个变异都被抓
```

三套测试：

| 套件 | 项数 | 覆盖 |
|---|---|---|
| 重建逻辑与导出安全 | 67 | 多帧解压、edit 回放、read 重同步、路径穿越、导出隔离 |
| 文案一致性与错误码 | 15 | 中英键集、每个错误码有翻译、无死键、占位符一致 |
| 真实会话端到端 | 15 | 拿本机真实会话重建并导出，逐字节比对 |

第二套之所以存在，是因为「翻译漏了」不会报错——界面只会显示一个原始机器码，
而没人会注意到直到用户看见。

**变异测试**是这个插件的可信度来源：97 项全绿本身不说明问题，只有「把多帧解压
改回只解第一帧、把 read 重同步删掉、把路径穿越检查拆掉之后，测试必须变红」，
才能说明这些断言真的在守着东西。12 个变异全部被抓住。

`tools/e2e-real-session.mjs` 依赖本机存在会话记录；没有时整组 skip 而不是失败，
那是环境不同，不是代码坏了。

## 目录

```
lib/session.js   读会话：切多帧 zstd → 解析事件 → 收集工具调用
lib/scan.js      找会话、列出摘要
lib/rebuild.js   回放 write/edit/read → 重建文件树
lib/export.js    安全导出（拒绝穿越、拒绝写回工作区）
index.js         Host：/api/session-restore/{sessions,preview,file,export,status}
client.js        界面：会话列表 → 文件列表 → 单文件查看
tools/           测试与诊断脚本
```
